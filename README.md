# GitHub 仓库接入体检

粘贴一个公开 GitHub 仓库链接，自动检查 README、依赖清单、启动脚本、Windows 专用脚本、硬编码路径与敏感信息风险，并给出 100 分制的接入就绪度、等级、主要风险清单和整改建议。

## 本地运行

环境要求：Node.js 20.9+（推荐 22 LTS 或更高）。

```bash
npm install
npm run dev
```

打开 http://localhost:3000，输入仓库链接即可。生产构建：

```bash
npm run build
npm start
```

## 可选配置

复制 `.env.example` 为 `.env.local`，按需填写：

| 变量 | 作用 |
| --- | --- |
| `GITHUB_TOKEN` | 可选。提高 GitHub API 限额（未登录约 60 次/小时）。 |
| `AI_API_KEY` | 可选。配置后调用 OpenAI 兼容接口生成接入建议。 |
| `AI_BASE_URL` | 可选。默认 `https://api.openai.com/v1`，可换成其他兼容服务。 |
| `AI_MODEL` | 可选。默认 `gpt-4o-mini`。 |

未配置 AI Key 时，工具会使用本地规则生成建议，并在页面标注“本地规则”，功能不会中断。配置了 AI 但请求失败时，也会自动回退本地规则建议，并在报告中提示。AI 只生成建议，不参与 100 分制评分；评分始终由本地规则计算。

## 检查内容

- README：是否存在，是否包含安装、启动、配置、依赖说明和代码示例。
- 依赖：package.json、requirements.txt、pyproject.toml、go.mod、Cargo.toml、pom.xml、composer.json、Gemfile、*.csproj 等，以及对应锁文件。
- 启动：npm scripts、根目录的 Makefile / Dockerfile / Docker Compose / Procfile、`.devcontainer/devcontainer.json`，以及 README 中的启动命令。识别为库 / SDK 项目时，按 README 的安装与使用示例评估，不强制要求启动脚本。
- Windows 专用脚本：`.bat`、`.cmd`、`.ps1`、`.vbs`；检查 README 是否提到 Windows / PowerShell 相关说明，以及是否提示 PowerShell 执行策略。
- 硬编码路径：`C:\`、`C:/`、`/Users/`、`/home/`、`/opt`、`/var/www`、`/mnt`、`/srv`、`/root`、`/Volumes`、`/Applications` 及 UNC 共享路径。
- 敏感信息：常见云厂商 / 平台令牌（OpenAI `sk-`、AWS `AKIA`、腾讯云 `AKID`、Google API Key、Stripe 线上密钥、npm 发布令牌、GitHub / GitLab / Slack Token）、Bearer、JWT、私钥块和疑似硬编码凭据，以及 `.env` 文件入库和根目录 `.gitignore` 覆盖情况。

## 评分规则

| 维度 | 分值 |
| --- | --- |
| README 文档 | 20 |
| 依赖与锁定 | 20 |
| 启动脚本 | 20 |
| Windows 适配 | 15 |
| 硬编码路径 | 10 |
| 敏感信息 | 15 |

等级：85 分及以上 A，70–84 B，55–69 C，55 分以下 D。A 表示接入风险低，B 表示整体可控，C 表示存在明显缺口，D 表示阻断项较多。

每个维度下方会显示得分依据，页面里还可以展开查看评分规则。出现高危敏感信息时，“敏感信息”维度直接记 0 分。

## 数据来源与扫描边界

- 文件树和仓库元数据优先来自 GitHub REST API。文件树接口不可用时，会切换到 jsDelivr 备用源；仓库信息接口失败时，Star、语言、许可证等元数据可能显示为未知，报告中会明确提示。
- 文件内容优先从 raw.githubusercontent.com 读取，不可用时切换到 jsDelivr CDN。
- 只支持公开 GitHub 仓库；私有仓库、非 GitHub 域名和非法链接会直接返回错误提示。
- 只分析一个分支的当前文件：优先使用链接中指定的分支，未指定或读取失败时使用仓库默认分支；不扫描其他分支或 Git 历史。
- 扫描上限：最多读取 100 个文件，单文件 200 KB，总计 8 MB，按优先级抽样；优先 README、`.env` / 密钥类文件、Windows 脚本、依赖清单和配置。页面会显示实际扫描数量，未覆盖的部分不会假装已检查。
- 会自动跳过 `node_modules`、构建产物、依赖目录和二进制文件；锁文件只按路径识别，不读取内容。
- 风险条目与路径 / 敏感信息命中各最多展示 60 条，超出时报告中会提示。
- 仓库文件树被截断、文件读取失败、备用源缺元数据等情况都会在报告顶部明确提示。

## 更新跟踪（设计说明）

当前版本不保存报告，也不记录历史：每次分析都会按当时的分支实时拉取文件树、重新抽样扫描。所以隔一段时间再分析同一个链接，看到的必然是最新代码，但两次结果之间没有对比，也不标注“这份报告基于哪次提交”。

如果要把“跟踪后续更新”做成正式能力，设计如下。本节只描述方案，尚未实现。

### 怎么发现更新

- **先读分支指向哪次提交。** 分析开始时读一次分支 HEAD（`/repos/{owner}/{repo}/commits/{branch}`），拿到 commit SHA 和提交时间。只花一次请求，不读文件。
- **和报告里的基线比较。** 每份报告记录分析时的 commit SHA。再次分析或点“检查更新”时先取 HEAD：SHA 相同就是没有新提交，直接告诉用户；不同才继续。
- **用条件请求省配额。** 仓库信息和 HEAD 请求都带上一次的 ETag（`If-None-Match`）。GitHub 返回 304 时不占限额，可以很便宜地确认“没变”。
- **文件树单独判断。** 递归树接口返回的根 tree SHA 没变，说明文件列表完全没变，连逐个文件比对都可以跳过。
- **由用户动作触发。** 默认在用户再次分析或点“检查更新”时执行，不做后台定时轮询。以后若支持订阅，也只对用户主动关注的仓库执行，并且先走条件请求。
- **基线从哪来。** 报告本身记录 SHA；浏览器保留最近一次结果，或在服务端缓存里留一份基线。两者都没有时按首次分析处理，照常全量扫描。

### 怎么避免全量重算

- **文件级复用。** 文件树里每个文件都带 blob SHA。上次分析保存“路径 → blob SHA”清单（只存 SHA，不存文件内容），和新树对比出新增、修改、删除、重命名，只重新读取 SHA 变化的文件。抽样名单始终按最新文件树重算，新文件不会被漏掉。
- **维度级复用。** 每个检查维度声明依赖哪些文件：README 只看 README，依赖维度看清单和锁文件，启动维度看清单、README 和启动脚本，Windows 维度看脚本和 README，路径与敏感信息看所有已读文件。依赖文件都没变，就沿用该维度上次的得分和命中；变了才重算这一维。
- **汇总始终重算。** 总分、等级和风险排序用最新维度结果重新汇总，开销很小，也避免出现缓存分数和明细对不上。
- **报告级缓存。** 同一 commit、同一规则版本的报告可以整体命中缓存（进程内小型缓存，带过期时间和条数上限），连文件都不用读。
- **规则版本参与缓存键。** 规则一改，旧缓存自动失效，不会出现新旧规则混用。
- **只缓存必要信息。** 缓存里放 blob SHA、规则版本、维度得分和脱敏后的命中信息，不放仓库原文。缓存丢失、进程重启或多实例部署时退化为全量扫描，结果不变，只是更慢、更耗配额。

### 报告怎么标注所基于的 commit

- 报告头部增加“分析基线”：分支、commit SHA 短值、提交时间，例如 `main @ a1b2c3d · 2026-11-20 14:32`，并链接到 GitHub 的对应 commit 页面。
- 同时显示规则版本和扫描时间。三者一起回答“这份结论对应哪份代码、用哪套规则、什么时候跑的”。
- 文件树和文件内容都按 commit SHA 读取（raw.githubusercontent.com 和 jsDelivr 都支持用 SHA 代替分支），分支继续前进时报告不会“漂移”；复查旧报告时按报告里的 SHA 重新分析即可。
- 增量分析时，报告显示与上次的差异：文件新增 / 修改 / 删除数量、分数变化、风险新增与关闭，并分别标出哪些维度是复用的、哪些是重新扫描的。
- 仍然只分析一个分支的当前状态，不遍历 Git 历史；“对比”只发生在两次分析之间。

### 失败或限流时怎么兜底

- **确认不了更新。** HEAD 请求超时、鉴权失败或被限流时，不覆盖已有报告，也不假装是最新结果。报告顶部写明“未能确认是否有新提交，本报告基于 `<sha>`，检查于 `<时间>`”。
- **限流。** 读取 `x-ratelimit-reset` 告诉用户何时可以重试；配置 `GITHUB_TOKEN` 可以抬高限额。发现更新本身只花一次请求，条件请求命中 304 时不占额度，正常使用不会把限额打满。
- **文件树拿不到。** 先按链接中的分支、默认分支重试，再切 jsDelivr；都不行就退化为按上次路径清单全量扫描，并在报告顶部写明文件列表可能不完整。
- **增量读取失败。** 某个文件这次读不到，保留上次的结果并标注“该文件本次未能读取，沿用旧结果”；如果它属于评分关键项（README、依赖清单、启动脚本），对应维度标注“可能过期”，不把旧结论当新结论。
- **缓存不可用。** 直接全量扫描。扫描数量、上限和来源照常显示，不会因为走增量而缩小扫描范围。
- **AI 建议。** 仓库更新后重新生成；失败时沿用本地规则建议（现有逻辑）。如果继续使用上一次的 AI 建议，必须标注它生成时的 commit，避免旧建议被误认为基于最新代码。

## 安全说明

- 只读分析公开仓库，不下载完整仓库、不保存代码、不写数据库。
- 密钥内容在服务端脱敏后才返回页面，完整值不会出现在页面、日志或 AI 请求中。
- 调用 AI 时只发送聚合后的检查结果和风险标题/建议，不发送文件内容和完整密钥；请求发往 `AI_BASE_URL` 指定的服务。
- 结果由自动化规则生成，可能存在误报，不能替代安全审计。
